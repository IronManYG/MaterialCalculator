## Step 1 — Internal testing track upload

Always upload to Internal first. Never push straight to Production — this is the validated rollout sequence from the v1.2.0 ship and is documented in memory `project_signing_and_rollout.md`.

1. Open **Play Console** → select the **Sifr (Material Calculator)** app.
2. Left sidebar → **Testing → Internal testing**.
3. **Create new release** button (top right).
4. Drag-drop `app\build\outputs\bundle\release\app-release.aab` into the **App bundles** section.
5. Play Console validates the AAB (versionCode 6, namespace, signing) — takes 30–60 seconds.
6. **Release name** auto-fills as `6 (1.3.0)` — leave it.
7. **Release notes** — paste the bilingual notes from §Release notes below.
8. **Save** → **Review release** → **Start rollout to Internal testing**.

## Step 2 — Smoke test via Play Store Internal install

1. On the test device (Honor 400 Pro is the primary per memory `reference_honor_400_pro_haptics.md`): open the Play Store app.
2. Search **Sifr** or open the listing URL — should see "Internal testing" tag if the account is enrolled as an internal tester (per Phase 1 setup).
3. Tap **Update** — pulls versionCode 6 over live versionCode 5.
4. 5-minute smoke test:
   - Open Sifr; verify new launcher icon + name.
   - Basic: `12 + 5 =` → `17`.
   - Toggle Scientific (🧪 chip) → `sin(30) =` → `0.5` (degrees mode default).
   - Memory: type `42`, M+, MC, MR → cycle works (M chip lights up after M+, clears after MC, restores after MR).
   - Rotate to landscape — keypad + scientific block side by side; status bar hidden.
   - Settings → Theme: System / Light / Dark — all three apply immediately app-wide.
   - History — open via the History icon, see the recent calculations from the smoke test.
   - Switch device locale to Arabic in system settings → app strings flip to Arabic, keypad stays LTR-locked, back arrow mirrors correctly.

Stop the smoke test once everything looks correct. If any check fails — pause shipping, investigate, rebuild and re-upload.

## Step 3 — Refresh store listing (BEFORE production promotion)

Listing changes propagate within minutes — no review delay for screenshot/text-only updates. Do this before promoting Internal → Production so users on day-one of v1.3.0 see the rebranded listing.

Navigate to: **Play Console → Grow → Store presence → Main store listing**.

### Step 3.3 — Graphics: app icon + feature graphic (DEFER to a later release)

Play Console flags these as required (`*`) and they currently still carry the HG Calculator-era assets:

- **App icon** — 512 × 512 px, 32-bit PNG, max 1 MB. The in-app launcher icon has already been rebranded to Sifr (Phase 2.1, see memory `project_phase2_1_status.md`), but the **Play Console listing's icon** is a separate upload that wasn't refreshed. Needs export at 512×512 from the in-app `ic_launcher` source.
- **Feature graphic** — 1024 × 500 px banner displayed at the top of the listing on web and on Featured pages. Needs design work — doesn't exist yet.

**Why defer.** These need design work (or at least asset export) and are non-blocking for the v1.3.0 release — Play Console will accept the production rollout with the old icon and feature graphic still attached. The text + screenshot refresh in 3.1 and 3.2 above is already a major listing improvement.

**When to do it.** Bundle into **Phase 2.11** (tech debt + polish) or a dedicated `chore/listing-graphics` PR. Track in memory `project_phase2_11_backlog.md` once the v1.3.0 ship is complete.

## Step 4 — Promote Internal → Production

1. Once Step 2 smoke test passes — Play Console → **Production → Releases → Create new release**.
2. Top right → **Promote from Internal testing** → select the v1.3.0 internal release. AAB is reused; no re-upload.
3. Release notes — Play Console offers to copy from the Internal release. Accept.
4. **Review release** → **Start staged rollout**.
5. **Recommended rollout %: 20% for the first 24h.** Safety margin given v1.3.0 is a big jump from v1.2.0 (rebrand + Phase 2.0 → 2.10 features).
6. Submit for Google review. Usually clears in a few hours, occasionally up to 24h.

## Step 5 — Watch Vitals + ramp to 100%

1. 24h after rollout starts → Play Console → **Quality → Android vitals**.
2. Targets:
   - Crashes: < 0.1% sessions
   - ANRs: < 0.05% sessions
   - Excessive wakeups: dashboard green
3. If quiet — Production → Releases → edit the v1.3.0 release → **Increase rollout** → 50% → wait another 12–24h → 100%.
4. If a crash spike — **halt rollout immediately**, investigate via Play's crash dashboard (per memory `user_project_purpose_sifr.md`, the crash-dashboard learning loop is an explicit goal for this project).

## v1.3.0 user-facing changes (for marketing / blog posts)

Rolled up from Phase 2.0 → 2.10 (PRs #12 through #26 plus the post-release cleanups #29/#30/#31/#32):

- **Sifr rebrand** — new name + identity (Arabic: صفر = zero). Previous name "Material Calculator" was a generic dev-tutorial-era placeholder.
- **Scientific mode** — trigonometric functions (sin, cos, tan + inverses), π, e, log, ln, √, factorial. Toggle via 🧪 chip; persists via DataStore. Always visible in landscape regardless of toggle.
- **Memory keys** — MC, M+, M−, MR. M chip in display lights when memory is non-zero.
- **Adaptive landscape** — `WindowSizeClass`-driven layout. Basic + scientific blocks side by side; mirrored under Arabic RTL.
- **Editable cursor** — tap anywhere in the expression to position the cursor and type/delete at that position (Phase 2.9).
- **Live result preview** — partial results render while you type, before pressing `=`.
- **Auto-shrink display** — long expressions shrink rather than overflow.
- **History** — past calculations persisted via Room. Tap-to-restore. Clear-all with confirmation.
- **Settings** — theme (System/Light/Dark), haptics on/off, error sounds on/off. All persist via DataStore.
- **Improved Arabic locale** — RTL-correct toolbar positioning, absolute-left divider, LTR-locked keypad, Arabic translations for all visible strings.
