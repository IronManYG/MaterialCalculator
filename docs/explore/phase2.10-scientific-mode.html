Phase 2.10 — Scientific Mode & Memory Functions

Add an advanced/scientific calculator mode alongside the existing basic mode, plus the four classic memory keys (MC, M+, M−, MR). This is a feature push that builds on the parser/evaluator/MVI foundation hardened in Phases 2.8–2.9.

Draft 2026-05-12 · Branch feature/phase2.10-scientific-mode · Hussain G.

In scope

  • Mode toggle (basic ↔ scientific) with persisted preference
  • Scientific ops: sin/cos/tan + inverses, log, ln, e^x, π, e, x², √, x^y, x!, deg/rad toggle
  • Memory: MC, M+, M−, MR with persistence across process death
  • Parser/evaluator extension (additive — no rewrite)
  • Arabic copy + RTL preview for new buttons
  • @Preview coverage for both modes
  • Tests for every new operation + memory flow

Out of scope

  • Tip calc, unit conversions, NL parsing, custom formulas (separate phases)
  • Tablet/large-screen adaptive layout (deferred to future)
  • Graph plotting, symbolic math, complex numbers
  • History entries showing the scientific function names (basic display still wins; revisit later)
  • New theme picker (separate phase)

4 · Architecture decisions

Parser / evaluator

Extend, don't rewrite. The current grammar:

expression → term (± term)*
term       → factor (×|÷|% factor)*
factor     → number | (expression) | ±factor

Becomes:

expression → term (± term)*
term       → power (×|÷|% power)*
power      → unary (^ power)?          ← new, right-associative
unary      → ±unary | postfix
postfix    → primary (!)*              ← new, factorial
primary    → number | constant | function | (expression)
function   → name "(" expression ")"   ← sin, cos, ln, log, sqrt, exp, …
constant   → "π" | "e"

New ExpressionPart variants: Function(name), Constant(name), Postfix(op). Existing Number, Op, Parentheses stay.

State model

CalculatorState(
    expression: String,
    cursor:     Int,
    livePreview: String?,
    mode:        CalculatorMode = Basic,    ← new
    angleUnit:   AngleUnit      = Radians,  ← new
    memoryValue: Double?         = null,    ← new
)

CalculatorMode ∈ { Basic, Scientific }. AngleUnit ∈ { Degrees, Radians }. Memory is null when cleared.

Recommended path

Layout A (portrait) + A-Land (landscape) + Memory M1 — toggle in toolbar; scientific rows visible in scientific mode; landscape exposes both blocks side-by-side; memory row always visible. Closest analogue to the iOS/Samsung scientific calculator, surfaces every key without a hidden gesture, keeps basic-mode UI close to today's, and earns "free" scientific mode in landscape via WindowSizeClass.

Open questions before plan-mode

  1. Default angle unit — degrees or radians? Most consumer calculators default to degrees (Samsung, iOS). Academic / engineering use radians. Recommend: degrees, override via toggle.
  2. Constants display — when user presses π, do we write π into the expression and evaluate symbolically, or substitute 3.14159… at press time? Recommend: keep the symbol; evaluate at =. Cleaner display.
  3. Implicit multiplication — should 2π work, or require 2×π? Recommend: require explicit ×, like today's parser. Matches existing behavior, no parser ambiguity.
  4. Factorial domain — integers only, or extend to Γ(n+1) for non-integers? Recommend: integers ≥ 0, domain error otherwise. Keeps evaluator simple.
  5. Memory display — show an M chip in the toolbar when memory is non-null? Recommend: yes. Tiny, useful, costs nothing.
