# Phase 2.2b — MVI Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert `CalculatorViewModel` from `mutableStateOf<String>` to `StateFlow<CalculatorState>`, split `CalculatorScreen` into `CalculatorRoot` + `CalculatorScreen` per the project MVI convention, add test infra (`MainDispatcherRule`), and add 4 ViewModel unit tests including the reviewer-flagged "Calculate-on-Error" test.

**Parent spec:** `docs/superpowers/specs/2026-05-09-phase2.2b-mvi-refactor.md` (full design rationale, including why the `CalculatorEvent` channel is deferred to Phase 2.3).

**Architecture:** Six-stage refactor with atomic commits.
- **Stage A (Task 2):** Add `kotlinx-coroutines-test` + `turbine` to the version catalog and `app/build.gradle.kts`. Pre-flight for the test infra.
- **Stage B (Task 3):** Create `CalculatorState` data class.
- **Stage C (Task 4):** Port `CalculatorViewModel` to `MutableStateFlow<CalculatorState>`. Existing instrumented test must still pass (it goes through `MainActivity` which is the consumer).
- **Stage D (Task 5):** Split `CalculatorScreen` into `CalculatorRoot` + `CalculatorScreen(state, onAction)`, update `MainActivity` to call `CalculatorRoot()`, add `@Preview`. Clean up unused `viewModel` field in `CalculatorScreenTest`.
- **Stage E (Task 6):** Add `MainDispatcherRule` under `app/src/test/java/.../core/ui/util/`.
- **Stage F (Task 7):** Add `CalculatorViewModelTest` (4 tests). Includes the reviewer-flagged backlog item "Calculate-on-Error stays Error".
- **Stage G (Task 8):** Final verification + PR.

**Tech stack:** No toolchain change. Adds two test-only deps (`kotlinx-coroutines-test 1.11.0`, `turbine 1.2.1`).

**Branch:** `feature/phase2.2b-mvi-refactor` (already cut off `feature/phase2.2a-package-restructure`).

**Constraints:**
- Behavior is observably identical pre- and post-refactor — same buttons produce the same expressions/results.
- All 12 existing unit tests still pass at every checkpoint.
- The test count grows from 12 → 16 (4 new VM tests). No test count goes down.
- `applicationId`, namespace, `versionCode/Name`, theme, AGP version — all unchanged.
- `CalculatorEvent` channel + `ObserveAsEvents` are NOT added in this phase. (See spec section 1 for why.)
- `CalculatorRoot` keeps `viewModel = viewModel()` (factory from `androidx.lifecycle.viewmodel.compose`); Koin's `koinViewModel()` lands in Phase 2.2c.
- Dependency versions for the two new libs MUST be sourced via the registry (not from memory). The version literals locked in this plan (`1.11.0`, `1.2.1`) were verified at spec time against `https://repo1.maven.org/maven2/...`.

**Pre-execution check:** Branch is `feature/phase2.2b-mvi-refactor`, working tree is clean, `./gradlew :app:assembleDebug` and `./gradlew test` baseline both pass (12 unit tests; the file layout is the post-2.2a layout — `feature/calculator/{domain,ui,ui/components}` and `core/ui/theme`).

## Task 4: Port `CalculatorViewModel` to `MutableStateFlow<CalculatorState>`

**Files:**
- Modify: `app/src/main/java/dev/gaddal/sifr/feature/calculator/ui/CalculatorViewModel.kt`

`CalculatorScreen` and the instrumented test still read the old `viewModel.expression` API after this commit — they get fixed in Task 5. To keep this commit green, **add a temporary delegate property** `expression` that reads from `_state.value.expression`. It gets removed in Task 5.

- [ ] **Step 1: Replace the file content**

```kotlin
package dev.gaddal.sifr.feature.calculator.ui

import androidx.lifecycle.ViewModel
import dev.gaddal.sifr.feature.calculator.domain.CalculatorAction
import dev.gaddal.sifr.feature.calculator.domain.ExpressionWriter
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update

class CalculatorViewModel(
    private val writer: ExpressionWriter = ExpressionWriter(),
) : ViewModel() {

    private val _state = MutableStateFlow(CalculatorState())
    val state: StateFlow<CalculatorState> = _state.asStateFlow()

    // Removed in Task 5 once CalculatorScreen reads from `state` instead.
    val expression: String get() = _state.value.expression

    fun onAction(action: CalculatorAction) {
        writer.processAction(action)
        _state.update { it.copy(expression = writer.expression) }
    }
}
```

The temporary `expression` getter is tagged with a removal comment — explicit because it would otherwise look like permanent API.

- [ ] **Step 2: Build + tests green**

`./gradlew :app:assembleDebug && ./gradlew test`
Expected: BUILD SUCCESSFUL. 12 tests still pass.

- [ ] **Step 3: AndroidTest still compiles**

`./gradlew :app:assembleDebugAndroidTest` → BUILD SUCCESSFUL.

- [ ] **Step 4: Commit**

```bash
git add app/src/main/java/dev/gaddal/sifr/feature/calculator/ui/CalculatorViewModel.kt
git commit -m "Port CalculatorViewModel to StateFlow<CalculatorState>

Phase 2.2b stage C: replace the mutableStateOf<String> exposure
with MutableStateFlow<CalculatorState> + StateFlow exposure.

package dev.gaddal.sifr.core.ui.util

import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.ExperimentalCoroutinesApi
import kotlinx.coroutines.test.TestDispatcher
import kotlinx.coroutines.test.UnconfinedTestDispatcher
import kotlinx.coroutines.test.resetMain
import kotlinx.coroutines.test.setMain
import org.junit.rules.TestWatcher
import org.junit.runner.Description

@OptIn(ExperimentalCoroutinesApi::class)
class MainDispatcherRule(
    val testDispatcher: TestDispatcher = UnconfinedTestDispatcher(),
) : TestWatcher() {
    override fun starting(description: Description) {
        Dispatchers.setMain(testDispatcher)
    }

    override fun finished(description: Description) {
        Dispatchers.resetMain()
    }
}
```

## Rollback strategy

Per Phase 2.2a's rollback strategy: every task is one commit. If verification fails, fix the commit (amend pre-PR), or `git reset --hard HEAD~1` to redo the task. If the entire approach proves wrong mid-plan, `git checkout development && git branch -D feature/phase2.2b-mvi-refactor` discards everything cleanly.

The `kotlinx-coroutines-test` and `turbine` deps are test-only and have zero impact on production APK / AAB — adding them is risk-free.
