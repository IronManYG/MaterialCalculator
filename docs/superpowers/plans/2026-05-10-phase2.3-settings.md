# Phase 2.3 — Settings Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Ship the Settings feature end-to-end. DataStore-backed preferences (theme mode, haptics, sound), Settings screen reachable from Calculator, theme application live across the app, persistence across restart.

**Parent spec:** `docs/superpowers/specs/2026-05-10-phase2.3-settings.md` (full design rationale and component layouts).

**Architecture:** Ten-stage feature build with atomic commits.

| Stage | Task | What lands |
|---|---|---|
| A | Task 2 | DataStore + kotlinx-serialization deps; serialization plugin alias |
| B | Task 3 | Domain models — `AppSettings`, `ThemeMode` |
| C | Task 4 | `SettingsRepository` interface + DataStore-backed impl |
| D | Task 5 | `coreDataModule` (DataStore singleton) + `settingsModule` (repo + VM) wired into `appModules` |
| E | Task 6 | Settings UI — State / Action / Event / VM / Root / Screen + string resources |
| F | Task 7 | `@Serializable` on routes + `SettingsRoute` + switch to `rememberNavBackStack` |
| G | Task 8 | `CalculatorEvent` channel + `ObserveAsEvents` utility + `SettingsClicked` action |
| H | Task 9 | Settings IconButton on Calculator + `CalculatorRoot(onNavigateToSettings)` + `NavRoot` wiring + `dropUnlessResumed` |
| I | Task 10 | `SifrTheme(themeMode: ThemeMode)` + `MainActivity` reads themeMode flow via Koin |
| J | Task 11 | Final verification + PR |

The order matters: each stage either compiles green on its own (data + module + UI compiles before nav wiring), or short-circuits a forward reference cleanly (e.g. `CalculatorViewModel` gains the `events` flow before `CalculatorRoot` consumes it).

**Tech stack:** Adds three production deps:
- `androidx.datastore:datastore-preferences:1.2.1`
- `org.jetbrains.kotlinx:kotlinx-serialization-core:1.11.0`
- Kotlin compiler plugin `org.jetbrains.kotlin.plugin.serialization:2.3.21` (matches project Kotlin)

**Branch:** `feature/phase2.3-settings` (off `development`).

**Constraints:**
- All 16 existing unit tests still pass at every checkpoint.
- `applicationId`, namespace, `versionCode/Name`, AGP version — all unchanged.
- DataStore keys `theme_mode`, `haptics_enabled`, `sound_enabled` are LOCKED on first ship — never rename without a migration.
- Settings UI uses `R.string.*` from day one (Arabic translations land in Phase 2.5).
- No `SettingsViewModelTest` in this PR (deferred — see spec section 2.20). Add as follow-up if reviewer pushes back.

**Pre-execution check:** Branch is `feature/phase2.3-settings` (off `development` 2.2d-merged tip), working tree is clean (modulo `.idea/` files), baseline `./gradlew :app:assembleDebug` and `./gradlew test` pass with 16 unit tests.

## Rollback strategy

Each commit reverts cleanly:

- After Task 2 (deps): revert removes deps + plugin.
- After Task 3-6 (domain + repo + DI + UI): revert removes the entire `feature/settings/` subtree + `core/data/` and `core/domain/settings/` subtrees + Koin module wiring.
- After Task 7 (saveable routes): revert restores `remember { NavBackStack<NavKey>(...) }` and removes `@Serializable` + `SettingsRoute`.
- After Task 8 (events infra): revert removes `CalculatorEvent`, `ObserveAsEvents`, `SettingsClicked`, the VM `when` dispatch.
- After Task 9 (calc-side wiring): revert restores `CalculatorRoot()` with no nav lambda, removes the icon button.
- After Task 10 (theme application): revert restores `SifrTheme(darkTheme = isSystemInDarkTheme())` and removes MainActivity injection.

Full PR is one revert if needed.
