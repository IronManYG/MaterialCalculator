# Phase 2.2c — Koin DI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce Koin DI to the Calculator screen. Add `App : Application`, a `calculatorModule` providing `ExpressionWriter` + `CalculatorViewModel`, an `appModule` aggregator, and switch `CalculatorRoot` to `koinViewModel()`. Drop the now-redundant `ExpressionWriter` default arg on `CalculatorViewModel`.

**Parent spec:** `docs/superpowers/specs/2026-05-09-phase2.2c-koin-di.md` (full design rationale, including why `coreDataModule` and `koin-test` are deferred).

**Architecture:** Four-stage refactor with atomic commits.
- **Stage A (Task 2):** Add Koin BOM 4.2.1 + `koin-android` + `koin-androidx-compose` to the catalog and `app/build.gradle.kts`. Pre-flight for everything that follows.
- **Stage B (Task 3):** Create `App : Application` and register `android:name=".App"` in the manifest. Koin not yet wired (no modules) — but the Application class hooking is its own commit so a failure here is clearly attributable.
- **Stage C (Task 4):** Create `calculatorModule` and `appModule` aggregator. Wire `startKoin { modules(appModules) }` in `App.onCreate`. Production code now boots with the Koin graph populated, but composables still use the lifecycle-compose `viewModel()` factory — Koin is dormant.
- **Stage D (Task 5):** Switch `CalculatorRoot` to `koinViewModel()`. Drop `ExpressionWriter` default arg on `CalculatorViewModel`. Update the 4 unit-test constructor calls. Koin is now load-bearing.
- **Stage E (Task 6):** Final verification + PR.

**Tech stack:** No toolchain change. Adds three production deps via the Koin BOM:
- `io.insert-koin:koin-bom:4.2.1` (BOM platform import)
- `io.insert-koin:koin-android` (versioned by BOM)
- `io.insert-koin:koin-androidx-compose` (versioned by BOM, provides `koinViewModel()`)

**Branch:** `feature/phase2.2c-koin-di` (off `development` after 2.2b merged via PR #15).

**Constraints:**
- Behavior is observably identical pre- and post-phase — same buttons produce the same expressions/results.
- All 16 existing unit tests still pass at every checkpoint. Test count stays at 16 (no new tests; only constructor signature update on the 4 VM tests).
- `applicationId`, namespace, `versionCode/Name`, theme, AGP version — all unchanged.
- Koin BOM version `4.2.1` was verified at spec time against `https://repo1.maven.org/maven2/io/insert-koin/koin-bom/maven-metadata.xml` (latest stable 2026-04-09).
- The `appModule.kt` aggregator pattern is locked, even though it currently aggregates one module. It is the extension point for Phases 2.3 (settings) and 2.4 (history).

**Pre-execution check:** Branch is `feature/phase2.2c-koin-di`, working tree is clean, baseline `./gradlew :app:assembleDebug` and `./gradlew test` pass with 16 unit tests; file layout is the post-2.2b state.

## Task 3 — Add `App : Application` class + manifest registration

This commit registers the Application class but does NOT yet call `startKoin` (no modules to register yet). Splitting "Application class exists" from "Koin is wired" makes a manifest-level failure attributable.

Wait — actually combining the two means a single commit that brings up the Application class with `startKoin` makes more sense. The risk of a manifest issue is bounded; the value of having `App.kt` exist without doing anything is zero. **Decision:** combine.

- [ ] Create `app/src/main/java/dev/gaddal/sifr/App.kt`:
  ```kotlin
  package dev.gaddal.sifr

  import android.app.Application
  import dev.gaddal.sifr.di.appModules
  import org.koin.android.ext.koin.androidContext
  import org.koin.core.context.startKoin

  class App : Application() {
      override fun onCreate() {
          super.onCreate()
          startKoin {
              androidContext(this@App)
              modules(appModules)
          }
      }
  }
  ```
  Note: this references `appModules` which doesn't exist yet — that file is created in Task 4. **The build will be red between Task 3 and Task 4.** That's fine; the next commit is Task 4 which makes it green again. Atomic green-to-green is preferred when feasible, but here pulling a forward-reference makes the commit bisect-friendlier than a different ordering.

  **Revised plan:** swap Task 3 and Task 4 — create the modules first (Task 3) so when the App class is added (Task 4), everything compiles.

- [ ] **(Per revised plan, this task is now "create modules first" — see Task 3-revised below.)**

## Task 3 (revised) — Add `calculatorModule` + `appModule` aggregator

Modules exist before the Application class so `App.kt` can reference them in a single commit and stay green.

- [ ] Create `app/src/main/java/dev/gaddal/sifr/feature/calculator/di/CalculatorModule.kt`:
  ```kotlin
  package dev.gaddal.sifr.feature.calculator.di

  import dev.gaddal.sifr.feature.calculator.domain.ExpressionWriter
  import dev.gaddal.sifr.feature.calculator.ui.CalculatorViewModel
  import org.koin.androidx.viewmodel.dsl.viewModelOf
  import org.koin.core.module.dsl.factoryOf
  import org.koin.dsl.module

  val calculatorModule = module {
      factoryOf(::ExpressionWriter)
      viewModelOf(::CalculatorViewModel)
  }
  ```

- [ ] Create `app/src/main/java/dev/gaddal/sifr/di/AppModule.kt`:
  ```kotlin
  package dev.gaddal.sifr.di

  import dev.gaddal.sifr.feature.calculator.di.calculatorModule
  import org.koin.core.module.Module

  val appModules: List<Module> = listOf(
      calculatorModule,
  )
  ```

  > Note: `viewModelOf(::CalculatorViewModel)` requires that `CalculatorViewModel`'s constructor parameter (`ExpressionWriter`) is resolvable from the graph. The default arg on `CalculatorViewModel` is still in place at this checkpoint; Koin will inject the registered `ExpressionWriter` and the default is unused. The default arg is removed in Task 5.

- [ ] Run `./gradlew :app:assembleDebug` — expected: BUILD SUCCESSFUL. The modules exist but nothing references them yet.
- [ ] `git add app/src/main/java/dev/gaddal/sifr/feature/calculator/di/CalculatorModule.kt app/src/main/java/dev/gaddal/sifr/di/AppModule.kt`
- [ ] Commit: `Add calculatorModule + appModule aggregator`

## Rollback strategy

Phase 2.2c is fully reversible at any sub-stage:

- After Task 2 (deps added): revert removes Koin from the catalog + build script. No production code references Koin yet.
- After Task 3 (modules added): revert removes the two module files. Production code unchanged.
- After Task 4 (App class wired): revert restores `MainActivity` as the only entry point. The `App` class is unreferenced; manifest reverts the `android:name`.
- After Task 5 (load-bearing flip): revert restores the `viewModel()` factory call and the `ExpressionWriter` default arg. The 4 VM tests revert their constructor calls.

The full PR is a single revert if needed (the architectural change is small and self-contained).
