# Phase 2.2a — Package Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move source files from the flat `domain/` + `presentation/` + `ui/theme/` layout into the greenfield `core/` + `feature/calculator/` layout. Mechanical refactor only — zero behavior change, zero new dependencies, zero rename of public symbols.

**Parent spec:** `docs/superpowers/specs/2026-05-09-phase2.2-architecture-migration.md` (section 3 has the full file-move matrix and verification matrix).

**Architecture:** Four-stage move with atomic commits.
- **Stage A (Task 2):** Move main-source theme files into `core/ui/theme/`.
- **Stage B (Tasks 3–5):** Move main-source feature files into `feature/calculator/{domain,ui,ui/components}/`. One sub-package per commit.
- **Stage C (Task 6):** Update `MainActivity` imports (the only main file that doesn't move).
- **Stage D (Tasks 7–8):** Move test files (unit + instrumented) to mirror the new layout.
- **Stage E (Task 9):** Final verification + cleanup of any stranded empty directories.

**Tech stack:** No new tools. Same as Phase 2.1 baseline (Kotlin DSL, version catalog, Gradle 9.5.0, AGP 9.2.1, Kotlin 2.3.21, JDK 21 toolchain, BOM 2026.05.00).

**Branch:** `feature/phase2.2a-package-restructure` (already cut off `development` at the start of this session).

**Constraints:**
- `applicationId` stays `com.gaddal.materialcalculator` (unchanged from Phase 2.1).
- AGP `namespace` stays `dev.gaddal.sifr` (unchanged from Phase 2.1).
- `versionCode 5` / `versionName "1.2.0"` unchanged (no new release).
- All 12 unit tests pass at every checkpoint (no intermediate red states).
- Each commit must build clean.
- No public symbol renames in this plan. `SifrTheme` keeps its name. `CalculatorViewModel` keeps its `mutableStateOf<String>` shape — MVI port comes in Phase 2.2b.
- Variant `Constants.kt` files are NOT moved (they stay at the source-set root per Phase 2.2 spec §3.1).

**Pre-execution check:** Branch is on `feature/phase2.2a-package-restructure`, working tree is clean, baseline `./gradlew :app:assembleDebug` and `./gradlew test` both pass.

## Rollback strategy

Every task above is one commit. If verification fails at any task:

1. `git diff HEAD~1` to inspect the last commit.
2. If the issue is a missed import rewrite or a typo in a package decl, fix it and amend (`git commit --amend`) — these are pre-PR commits, amend is fine.
3. If the issue is structural (wrong directory chosen, wrong sub-package decision), `git reset --hard HEAD~1` and redo the task.
4. If the entire approach proves wrong mid-plan, `git checkout development && git branch -D feature/phase2.2a-package-restructure` resets cleanly with no impact on `development`.

The branch carries no migrations, no public-API changes, no behavior changes — rollback is purely local.
