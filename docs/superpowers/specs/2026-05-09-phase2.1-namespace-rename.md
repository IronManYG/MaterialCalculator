## 1. Context & Goals

Phase 2.0 modernized the build (Kotlin DSL, version catalog, Gradle 9.5, AGP 9.2.1, JDK 21). Phase 2.1 renames the Kotlin namespace and user-visible app label to the chosen brand **Sifr (صفر)** — Arabic for "zero", root of the English word "cipher".

**Why the rename matters:** The current namespace `com.example.materialcalculator` is the Android-Studio-template default. It signals "unfinished side project," conflicts with the actual brand (`com.gaddal`), and clutters every import in the codebase. Renaming now — before the architecture migration in Phase 2.2 — means the feature-folder layout lands on the correct namespace from day one.

**Why brand-first, not architecture-first:** The Phase 2.2 architecture migration moves every source file into a new feature-folder layout. Doing the namespace change in the same PR would conflate "where files live" with "what their package is" — two large mechanical refactors blurring into one diff. Splitting them keeps each PR's diff readable and rollback-able.

### Decisions locked

| Decision | Value | Rationale |
|---|---|---|
| Brand | **Sifr** (صفر) | Highest brainstorm score on cultural depth + brand-ability; "cipher" etymology gives free marketing copy |
| Namespace | `dev.gaddal.sifr` | Matches established `dev.gaddal.*` portfolio pattern; short, distinctive |
| `applicationId` | **STAYS `com.gaddal.materialcalculator`** | Preserves Play Store listing v1.2.0, install base, ratings — never change applicationId on a published app |
| App label EN | `Sifr` | Latin transliteration matches the namespace |
| App label AR (`values-ar/`) | `صفر` | Native Arabic word; auto-selected on Arabic-locale devices |
| Theme function | `MaterialCalculatorTheme` → **`SifrTheme`** | Bundled — keeping the old name with a new namespace would be inconsistent and confusing |
| Theme XML name | `Theme.MaterialCalculator` → **`Theme.Sifr`** | Same reasoning |
| `rootProject.name` | `MaterialCalculator` → **`Sifr`** | IDE project label and Gradle output paths |
| Repo name on GitHub | **Unchanged** (`MaterialCalculator`) | Out of scope; URL change has independent cost (CI, links, bookmarks). Track separately if desired. |

### What does NOT change

- `applicationId` (Play Store URL stays `https://play.google.com/store/apps/details?id=com.gaddal.materialcalculator`)
- `versionCode 5` / `versionName "1.2.0"` (no new release in this phase)
- Logo / app icon (separate effort)
- Play Store screenshots (regenerated in Phase 2.6)
- Play Store listing copy (separate marketing pass)
- Three build types and signing config
- Any dependency version
- The repo name on GitHub
- Domain registration / website

- [ ] **App Store collision search** — same on iOS even though we don't ship there yet, in case KMP-to-iOS becomes a Phase 3+ thing.
- [ ] **GitHub username/org check** — verify a `dev.gaddal.sifr` package is acceptable; no obvious clash with other developers using `gaddal` namespace.

## 3. Scope (file rename matrix)

### 3.1 Source files — directory move + package decl + import rewrites

All 25 Kotlin source files move from `app/src/<sourceset>/java/com/example/materialcalculator/...` to `app/src/<sourceset>/java/dev/gaddal/sifr/...`. For each file:

1. Move file under the new directory tree.
2. Rewrite top-line `package com.example.materialcalculator...` → `package dev.gaddal.sifr...`.
3. Rewrite any `import com.example.materialcalculator...` → `import dev.gaddal.sifr...`.

| Source set | Files | Notes |

### 3.5 Side-find (in-scope opportunistic fix)

`app/src/androidTest/java/.../ExampleInstrumentedTest.kt:22` asserts `appContext.packageName == "com.example.materialcalculator"`. This assertion was **already wrong** post-Phase-1: `packageName` returns the runtime `applicationId` (`com.gaddal.materialcalculator`), not the namespace. The test never failed because instrumented tests aren't running in the current dev flow (no GHA yet, no local emulator). Since we're touching the file anyway, fix the assertion to `"com.gaddal.materialcalculator"`.

## 5. Rollback strategy

The rename is mechanically large but conceptually simple — move directories, sed package strings. Rollback is therefore equally mechanical:

1. **Mid-phase rollback** (a single task fails, others completed): `git reset --hard HEAD~N` where N is the number of completed atomic commits in this phase. Each task in the plan is atomic, so individual rollback is granular.
2. **Whole-phase rollback** (PR merged but namespace breaks something later): revert the merge commit on `development`. Since `applicationId` doesn't change, no Play Store impact; revert is cosmetic.
3. **Nuclear rollback** (start over with a different brand): branch is throwaway, just delete and re-cut from `development`. Brainstorm artifact already lists the alternative (Raqam).

The atomic commit structure makes individual deviations easy to spot in `git log`.

## 6. Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| AGP / R8 caches stale data after namespace move | Medium | Build fails with "package not found" | Always run `./gradlew clean` between bulk file moves and rebuilds |
| IDE refactor "rename package" gets out of sync with `git mv` | Medium | Files in two places at once, build fails | Do all directory moves via `git mv` (not IDE refactor), then commit before any further edit |
| Theme function rename breaks an unnoticed reference | Low | Compile error, easy to fix | `grep -rn MaterialCalculatorTheme` exhaustive sweep in plan; verify zero matches after rename |
| Arabic `app_name` doesn't render correctly | Low | Locale-AR users see boxes | Use UTF-8 file encoding (default for `values-ar/strings.xml`); verify by installing on AR-locale device or changing device locale |
| `ExampleInstrumentedTest` side-find masked another bug | Very Low | Tests still pass when they shouldn't | Read the test thoroughly during the side-find fix; confirm the only issue is the assertion target string |
| Play Console upload key check fails because of namespace | **Zero** | n/a | Play App Signing keys off `applicationId`, not namespace. Namespace is purely a Kotlin-package concept; never reaches Play. |
