## 1. Context & Goals

Phase 2.2b reshaped `CalculatorViewModel` around `StateFlow<CalculatorState>` and split `CalculatorScreen` into `CalculatorRoot` + `CalculatorScreen`. `CalculatorRoot` currently constructs the ViewModel via the lifecycle-compose factory (`viewModel = viewModel()`), and `ExpressionWriter` is wired through a default constructor argument on `CalculatorViewModel`. There is no DI container; collaborators are constructed implicitly.

After this phase:

- **Koin** is on the classpath (BOM 4.2.1 → `koin-android` + `koin-androidx-compose`).
- An **`App : Application`** class lives at `app/src/main/java/dev/gaddal/sifr/App.kt` and calls `startKoin { ... }` in `onCreate`. The manifest's `<application android:name=".App">` references it.
- A **`calculatorModule`** at `feature/calculator/di/` provides `ExpressionWriter` (factory) and `CalculatorViewModel` (viewModel) via constructor-reference DSL (`factoryOf` / `viewModelOf`).
- A **thin aggregator** at `di/appModule.kt` exposes `val appModules = listOf(calculatorModule)` — extension point for `settingsModule` (Phase 2.3), `historyModule` (Phase 2.4), etc.
- `CalculatorRoot` switches `viewModel = viewModel()` → `viewModel: CalculatorViewModel = koinViewModel()`.
- `CalculatorViewModel`'s `ExpressionWriter` default arg is **dropped**; injection is the only path. The unit test passes `ExpressionWriter()` explicitly (one-line update to the existing 4 tests).

Behavior on screen and in `aapt2 dump badging` is identical pre- and post-phase. The user-visible app is unchanged; only construction wiring moved.

### Why Koin (and not Hilt or manual DI)

The greenfield spec section 2 already locked Koin as the DI choice for this project. The `android-di-koin` skill is the canonical pattern. Hilt's KSP/kapt overhead is unjustified for a single-VM app; manual DI scales poorly once Phase 2.3 (settings) brings a `SettingsRepository` + `SettingsViewModel`.

### Why drop the `ExpressionWriter` default arg

With `viewModelOf(::CalculatorViewModel)`, Koin resolves every constructor parameter from the graph. A default arg is never used in production once Koin is wired — the default is silent dead code with the false-friend property of looking like it's still doing work. Removing it makes the wiring explicit and matches the "DI is in charge now" statement.

The `factoryOf(::ExpressionWriter)` binding gives each VM its own fresh writer (matching today's per-VM-instance behavior) without making the writer a singleton. `factory` is the right scope: `ExpressionWriter` carries mutable expression state that should not be shared across ViewModel instances.

### Out of scope (deferred)

- **Repository / data-layer modules** — there are none yet. Phase 2.3 brings `SettingsRepository` + `settingsDataModule`.
- **`coreDataModule`** — premature; nothing to put in it.
- **Compose-Multiplatform-style `KoinApplication { ... }` wrapper in `MainActivity`** — Android-only project; the Application-class `startKoin` path is canonical.
- **`koin-test` artifact** — the existing unit test only constructs the VM directly with a fake-free real `ExpressionWriter`, so Koin's test verifier brings no value yet. Add when there's a module graph worth verifying (Phase 2.3+).
- **Navigation 3** — Phase 2.2d.

## 2. Component-by-component changes

### 2.1 `gradle/libs.versions.toml` (add Koin)

```toml
[versions]
# ... existing ...
koin = "4.2.1"

[libraries]
# ... existing ...
koin-bom = { group = "io.insert-koin", name = "koin-bom", version.ref = "koin" }
koin-android = { group = "io.insert-koin", name = "koin-android" }
koin-androidx-compose = { group = "io.insert-koin", name = "koin-androidx-compose" }
```

The two functional artifacts pin no `version.ref` — versions resolve through the BOM platform import in `app/build.gradle.kts`.

Latest stable verified at spec time against `https://repo1.maven.org/maven2/io/insert-koin/koin-bom/maven-metadata.xml` → **4.2.1** (published 2026-04-09). The BOM aligns `koin-android` and `koin-androidx-compose` to the same release train.

### 2.2 `app/build.gradle.kts` (add Koin deps)

```kotlin
dependencies {
    // ... existing ...

    // Koin DI
    implementation(platform(libs.koin.bom))
    implementation(libs.koin.android)

    // ... existing tests, etc.

```

Both Koin artifacts go to `implementation` (production code), not `testImplementation`.

### 2.3 `app/src/main/java/dev/gaddal/sifr/App.kt` (NEW)

```kotlin
package dev.gaddal.sifr

import android.app.Application
import dev.gaddal.sifr.di.appModules
import org.koin.android.ext.koin.androidContext
import org.koin.core.context.startKoin

class App : Application() {
    override fun onCreate() {
        super.onCreate()
        startKoin {
            androidContext(this@App)
            modules(appModules)
        }
    }
}
```

Lives at the package root alongside `MainActivity` (greenfield spec 2.1: top-level entry-points stay at the namespace root).

### 2.4 `app/src/main/AndroidManifest.xml` (one-line addition)

```xml
<application
    android:name=".App"
    android:allowBackup="true"
    ...
```

The single new attribute is `android:name=".App"`. Everything else stays.

### 2.5 `app/src/main/java/dev/gaddal/sifr/feature/calculator/di/CalculatorModule.kt` (NEW)

```kotlin
package dev.gaddal.sifr.feature.calculator.di

import dev.gaddal.sifr.feature.calculator.domain.ExpressionWriter
import dev.gaddal.sifr.feature.calculator.ui.CalculatorViewModel
import org.koin.androidx.viewmodel.dsl.viewModelOf
import org.koin.core.module.dsl.factoryOf
import org.koin.dsl.module

val calculatorModule = module {
    factoryOf(::ExpressionWriter)
    viewModelOf(::CalculatorViewModel)
}
```

Per the `android-di-koin` skill: prefer constructor-reference overloads. `ExpressionWriter` is a `factory` (fresh instance per resolution) because it owns mutable state that should not be shared across ViewModels.

### 2.6 `app/src/main/java/dev/gaddal/sifr/di/AppModule.kt` (NEW)

```kotlin
package dev.gaddal.sifr.di

import dev.gaddal.sifr.feature.calculator.di.calculatorModule
import org.koin.core.module.Module

val appModules: List<Module> = listOf(
    calculatorModule,
)
```

Thin aggregator. Adds `settingsModule`, `historyModule`, `coreDataModule` as those features land in 2.3+. Keeping it as a `List<Module>` (vs a single fat module) matches the skill's "one Koin module per feature layer" principle.

### 2.7 `feature/calculator/ui/CalculatorViewModel.kt` (drop default arg)

```kotlin
class CalculatorViewModel(
    private val writer: ExpressionWriter,
) : ViewModel() {
    // ... unchanged body ...
}
```

The only change is removing `= ExpressionWriter()` from the constructor parameter. With Koin in charge of construction, the default is silent dead code.

### 2.8 `feature/calculator/ui/CalculatorScreen.kt` (switch to `koinViewModel()`)

```kotlin
import org.koin.androidx.compose.koinViewModel

@Composable
fun CalculatorRoot(
    viewModel: CalculatorViewModel = koinViewModel(),
) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    CalculatorScreen(
        state = state,
        onAction = viewModel::onAction,
    )
}
```

Drops the `androidx.lifecycle.viewmodel.compose.viewModel` import and replaces it with `org.koin.androidx.compose.koinViewModel`.

### 2.9 `app/src/test/java/dev/gaddal/sifr/feature/calculator/ui/CalculatorViewModelTest.kt` (4 one-line updates)

Each test currently does `CalculatorViewModel()`. With the default arg dropped, each becomes `CalculatorViewModel(ExpressionWriter())`. No assertion or test-name changes.

```kotlin
val viewModel = CalculatorViewModel(ExpressionWriter())
```

The `ExpressionWriter` import is added at file-top.

### 2.10 Files NOT touched

- `MainActivity.kt` — still calls `CalculatorRoot()`. The `koinViewModel()` resolution happens inside `CalculatorRoot`, opaque to the activity.
- Theme files (`core/ui/theme/*`) — untouched.
- `CalculatorState.kt`, action/event types, button components — untouched.
- Instrumented test (`CalculatorScreenTest.kt`) — works through `MainActivity` and Koin's test setup is automatic in `androidTestImplementation` once `App` is on the manifest. **Verify the instrumented `assembleDebugAndroidTest` task still compiles**; full instrumented run requires an emulator (out of CI scope this phase).
- Variant `Constants.kt` files — untouched.
