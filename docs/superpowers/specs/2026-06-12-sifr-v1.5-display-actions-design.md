# Sifr v1.5 — "Display & Actions" — Design Spec

> **Status:** Approved 2026-06-12. Per-release implementation spec under the standing roadmap
> (`2026-06-11-sifr-redesign-roadmap-design.md`, §5 v1.5.0).
> **Branch:** `feature/v1.5-display-actions` (off `development` @ `68cb0c2`, which carries v1.4).
> **Codebase:** `dev.gaddal.sifr` · Compose · Material 3 · MVI + Koin + Nav3 · DataStore.
> **Design handoff:** `docs/design_handoff_sifr_redesign/` (`design-tokens.json`, `screen-specs.md`,
> `compose-implementation.md`, runnable `reference_prototype/` — visuals are LOCKED here, not re-explored).
> **Constraint:** `applicationId` stays `com.gaddal.materialcalculator`; namespace stays `dev.gaddal.sifr`.

## 1. What this is

v1.5 makes the **dormant display tokens real** and gives results something to **do**. v1.4 shipped the
`SifrColors` token layer with `displayBlock` / `displayInset` / `displayCard`, `eqGlow`, and
`SifrKeyStyle.innerTopHighlight` **populated in the palettes but rendered nowhere** — deliberate stubs.
v1.5 renders them and layers on result actions, fraction results, an M-chip with persistence, and three
new Settings sections.

**No engine changes.** Reuses the existing MVI plumbing (`CalculatorAction` / `CalculatorEvent`),
`FeedbackController` / `FeedbackIntent`, the `SifrColors` token layer, and the existing in-session memory
actions (`MemoryClear/Add/Subtract/Recall`). The handoff's `reference_prototype/app/engine.js` is a mirror,
not a port target.

## 2. Scope — six threads, one release

1. **Per-theme display containers** — Bayan ink block, Farah floating card, Mizan recessed inset.
2. **Two leftover v1.4 stubs** — Layl `=`-glow, Mizan inner-top key highlight (populated tokens, not yet drawn).
3. **Result-actions row** — `COPY` / `SHARE` / `ANS →`.
4. **Fraction results** — `Double.toFraction()` + display rendering, gated on a new setting (default **OFF**).
5. **M-chip indicator + `memoryValue` persistence** — survives `am force-stop`.
6. **Settings sections** — `DISPLAY` / `FEEDBACK` / `ABOUT`.

### Baked-in decisions (this release)

- **Fraction results default = OFF (opt-in).** Cleaner first impression; avoids surprising users with
  ungainly `n⁄d` on messy decimals. Enabled in Settings → DISPLAY.
- **Fold in the two v1.4 visual stubs.** Layl `=`-glow + Mizan inner-top highlight ship with the
  display-container work — they're token-backed already and complete the "display becomes real" story.
- **`memoryValue` lives in `AppSettings` / DataStore**, following the established pattern: `calculatorMode`
  and `angleUnit` already live there despite being calculator-runtime concerns.

## 3. Domain & data layer

### 3.1 Fraction model (pure, unit-tested)

New file `feature/calculator/domain/Fraction.kt`:

```kotlin
data class Fraction(val sign: Int, val whole: Long, val n: Long, val d: Long)

/** Continued-fraction approximation. Returns null for integers / non-representable values. */
fun Double.toFraction(): Fraction?
```

Faithful port of the handoff algorithm (`engine.js` `toFraction`, lines 184–206): 24-iteration
continued-fraction expansion, denominator capped at `d ≤ 9999`, convergence tolerance `1e-9`, returns
`null` when the fractional part `< 1e-12` (integer) or no representable fraction is found.

**Placement rationale:** domain, not presentation — the project unit-tests `domain/` with Google Truth, and
this algorithm earns a test table.

### 3.2 DataStore additions

Extend `AppSettings` (`core/domain/settings/AppSettings.kt`):

```kotlin
val fractionResults: Boolean = false,   // NEW — DISPLAY toggle, default off
val memoryValue: Double? = null,        // NEW — persisted M register
```

Extend `SettingsRepositoryImpl` with two preference keys:
- `fraction_results` → `booleanPreferencesKey`, default `false`.
- `memory_value` → `doublePreferencesKey`; **absent = null** (write only when memory is set, remove key on
  `MemoryClear`).

`hapticsEnabled`, `soundEnabled`, `angleUnit` are **already** persisted — v1.5 only surfaces them in new UI.

## 4. MVI wiring — result actions + memory persistence

### 4.1 Result actions

New `CalculatorAction`s: `CopyResult`, `ShareResult`, `UseAnswer`.

New `CalculatorEvent`s (alongside existing `NavigateToSettings` / `NavigateToHistory` / `PlayFeedback`):

```kotlin
data class CopyToClipboard(val text: String) : CalculatorEvent
data class ShareText(val text: String) : CalculatorEvent
```

`CalculatorScreen` handles them: Android clipboard (`ClipboardManager`) for COPY, `Intent.ACTION_SEND`
(`text/plain`) for SHARE, each with a `FeedbackController` confirmation (haptic/toast). The VM emits the
event carrying the current result string.

**ANS →** seeds the just-computed result back as the working expression. During implementation, verify it is
meaningfully distinct from Sifr's existing "result becomes the expression after `=`" behavior; **collapse it
to a no-op/remove the chip if it proves redundant** rather than ship a decorative button.

### 4.2 Memory persistence + M-chip

- The VM writes `memoryValue` to DataStore on `MemoryAdd` / `MemorySubtract` (set key) and `MemoryClear`
  (remove key); restores it into `CalculatorState.memoryValue` on init by reading the persisted settings.
- **M-chip** renders in the display **only when `memoryValue != null`**. The MC/M+/M−/MR key row already
  exists (`CalculatorActions.memoryRow`); no new keys.

## 5. Display rendering — decomposed

The current `CalculatorDisplay` (~300 lines: expression field + live preview + promotion animation) stays
**focused**. New responsibilities go into siblings/wrappers:

- **`CalculatorDisplaySurface`** (new) — themed slot wrapper that reads `displayBlock` / `displayCard` /
  `displayInset` and applies the per-theme treatment, wrapping the existing `CalculatorDisplay`:
  - **Bayan** — ink block: solid `displayBlock` bg, margin 14/18, padding 20/20/22, faint `٥` watermark
    (150sp, ~6% opacity, top-left, `pointerEvents=none`).
  - **Farah** — floating card: `displayCard` bg, radius 26dp, drop shadow `0 6px 24px`.
  - **Mizan** — recessed inset: `displayInset` bg, radius 14dp, inner shadow.
  - **Layl / Raqim** — flat (no container; tokens null).
- **`FractionLabel`** (new) — renders `Fraction` as `[−]whole ⁿ⁄d` (numerator super / denominator sub at 62%
  of result size, ~80% opacity, `displayResult` color). Gated on `fractionResults`.
- **`ResultActionsRow`** (new) — three hairline pill chips (`COPY` / `SHARE` / `ANS →`), end-aligned, 8dp
  gap, visible only when `justEvaluated && error == null`.
- **`MemoryChip`** (new) — pill, shown when `memoryValue != null`. Optional sibling DEG/RAD status chip is
  **minor** — include only if cheap; the angle unit's primary control now lives in Settings.
- **bayanDark contrast revert:** `displayResult` returns to `#2C3FE3` now that it renders on the light ink
  block (`#F2EDE0`), retiring the v1.4 flat-background accent workaround (the `0734140` fix).

## 6. Glow & highlight — real Gaussian blur on minSdk 24

A glow behind the `=` key is *additive light radiating from the key*, **not** a backdrop blur of the content
behind it — so the backdrop-blur APIs (and their limits) don't apply. We want a genuine Gaussian-blurred
accent glow that works on the full minSdk-24 range.

- **Layl `=`-glow — `BlurMaskFilter` rendered to a cached software `Bitmap`.**
  - **Why not `Modifier.blur`:** it requires API 31+ (RenderEffect); below 31 it's a silent no-op.
  - **Why not BlurMaskFilter drawn directly into the Compose `DrawScope`:** on a *hardware-accelerated*
    canvas, `BlurMaskFilter` is unsupported below **API 28** (Android 9) — the mask is clipped/ignored
    (the limitation CRED's Synth gates around). The cliff is **28, not 31**.
  - **The approach that covers API 24+:** draw the rounded-rect glow into an **off-screen software
    `android.graphics.Bitmap`** via a software `Canvas` with
    `Paint().apply { color = eqGlow; maskFilter = BlurMaskFilter(radius, NORMAL) }`. The blur runs on the
    software pipeline, so the API-28 hardware-accel limitation never applies — a real Gaussian glow on
    **every API ≥ 24**, no dependency.
  - **Cost:** the glow is static (one key, fixed accent), so build the bitmap **once** —
    `remember(keySize, eqGlow, blurRadius)` — and blit it behind the `=` key each frame in
    `drawBehind { }`. The bitmap is sized to `keySize + 2·blurRadius` so the soft edges aren't clipped.
  - **Libraries considered and rejected:** `me.trishiraj:shadowglow` (uses BlurMaskFilter but minSdk/
    API-28 behavior undocumented; bundles parallax/breathing/glow-trail we don't need) and
    `com.github.skydoves:cloudy` (a content/backdrop blur — wrong tool for a standalone glow). A
    self-contained ~30-line helper beats a dependency for one key.
- **Mizan inner-top highlight:** 1px inset top line drawn in the key background from
  `SifrKeyStyle.innerTopHighlight` (already populated for Mizan keyNum/keyOp/keyEq/keyFn). No blur needed.

Both render inside `CalculatorButton`. The glow bitmap helper is the one piece worth a focused unit/preview
check across API levels during implementation.

## 7. Settings sections

In `SettingsScreen` (currently: theme/appearance section + loose haptics & sound toggles):

- **DISPLAY** — fraction-results toggle (new `fractionResults` pref) + angle-unit segmented control
  (`angleUnit`, pref already exists; `DEG` / `RAD`).
- **FEEDBACK** — reparent the existing haptics + sound toggles under a `FEEDBACK` header; the sound toggle
  reads as **"Error sound."**
- **ABOUT** — display-only: `Sifr — صفر` + tagline + accent `٠` glyph. No interactive controls.

Row + section-label styling per `screen-specs.md` (tracked uppercase section labels, `dim`; row label
14.5sp `text`, sub-label 11.5sp `dim`; 1px `hairline` dividers). New copy goes in `strings.xml` +
`values-ar/strings.xml`.

## 8. Previews & testing

- **Previews are the visual contract** (agents can't see the app). `@Preview` coverage for every new/changed
  surface, sampled across the **relevant** palette × mode axes (no Cartesian noise):
  - Display containers — Bayan / Farah / Mizan each previewed in light + dark.
  - Glow → Layl; inner-top highlight → Mizan.
  - `ResultActionsRow` and `FractionLabel` — both states (present / absent), one representative palette + dark.
  - Settings DISPLAY / FEEDBACK / ABOUT sections.
- **Unit tests:** `toFraction()` table — ½, ⅓, ¾, exact integers (→ null), negatives, repeating decimals,
  denominator > 9999 (→ null), very small fractional parts. Existing **133 tests stay green**.
- Build gate before merge: `sh gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`.

## 9. Build order (for the implementation plan)

Each step independently previewable / testable:

1. Domain + data — `Fraction` + `toFraction()` (with tests); `fractionResults` + `memoryValue` DataStore keys.
2. Memory persistence — VM read/write + restore; M-chip indicator.
3. Display surface + per-theme containers (Bayan / Farah / Mizan) + bayanDark revert.
4. Glow (Layl) + inner-top highlight (Mizan) in `CalculatorButton`.
5. Result-actions row + COPY / SHARE / ANS → events and Screen handlers.
6. Fraction rendering in the display, gated on the setting.
7. Settings DISPLAY / FEEDBACK / ABOUT sections + strings (EN + AR).
8. Preview coverage, test pass, feature-polish walkthrough.
