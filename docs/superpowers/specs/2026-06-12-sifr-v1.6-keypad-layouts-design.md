## 1. What this milestone delivers

Selectable **keypad layouts**. The redesign roadmap names four (`Classic`, `Remix`, `Arc`, `Tape`); this milestone ships the layout-switching **infrastructure** plus **Remix** and **Arc**. **Tape is deferred to v1.7** (it is the one cross-cutting layout — its in-display history receipt needs the History repo + restore/nav wiring, a different kind of work from rearranging keys; roadmap decision #6 explicitly allows this split).

Concretely:
- `KeypadLayout` enum + DataStore persistence + a Settings **KEYPAD** section (mini-diagram layout picker + a **Memory keys** toggle).
- **Remix** — 4×5 grid, `0` spans 2 columns as a pill, top row swaps `()`→`⌫`.
- **Arc** — one-hand: 3-col number pad + four operator circles stacked on a quarter-arc + an oversized `=` circle, anchored bottom-end.
- The **Memory keys** toggle gates the `MC M+ M− MR` row, which today renders unconditionally.

### Locked decisions (this session)

1. **Scope = Remix + Arc; Tape → v1.7.** (All options carried the shared infra.)
2. **`Memory keys` defaults ON** — opt-out. Preserves v1.5 behavior; the memory row is the only way to *write* to M (the display M-chip is read-only), so defaulting OFF would hide a just-shipped feature and regress existing users on update.
3. **Keypad composable structure = "dispatch the basic block"** (Approach 1, §3). Sci block + memory row + the LTR/mosaic wrapper are written once; only the *basic block* varies by layout. Classic/Remix share one span-aware grid renderer (differ by data only); Arc is a bespoke `Box` composable; Tape (deferred) maps to the Classic block.
4. **Remix follows the handoff: no `()` key in basic mode.** It trades `()` for a dedicated `⌫`, and `=` takes the old backspace slot. Parentheses remain available in **Scientific** mode (its sci block has `(` `)`), and Classic keeps `()` in basic mode. Remix is the deliberately streamlined layout.

## 2. Constraints inherited

- **Engine parity (roadmap cross-cutting #6):** zero changes to `ExpressionWriter → ExpressionParser → ExpressionEvaluator`. Remix/Arc only rearrange existing `CalculatorUiAction`s, all mapping to existing `CalculatorAction`s. **Unit-test baseline stays 141.**
- **Keypad stays `LayoutDirection.Ltr`** in every layout and orientation (math reads L→R) — already enforced in `CalculatorButtonGrid`; preserved in `ArcKeypad`.
- **`applicationId` untouched** (`com.gaddal.materialcalculator`).
- **Previews are the visual contract** — every new/changed surface ships `@Preview` coverage across the relevant palettes/modes; Arc additionally at min/max key size.
- **Build with `sh gradlew`**, never `./gradlew`; never `git add gradlew`. `docs/` is gitignored (`git add -f`).

## 3. Architecture — dispatch the basic block

`CalculatorButtonGrid` (portrait) stays the single keypad entry point and keeps owning the forced-LTR scope and the mosaic/hairline background wrapper. Its new signature gains `layout: KeypadLayout` and `memoryKeysVisible: Boolean`. Render structure:

```
CalculatorButtonGrid(mode, angleUnit, layout, memoryKeysVisible, onAction, fontSize)
  └─ forced LTR + (mosaic/hairline background, grid layouts only)
       when (layout) {
         Arc            -> ArcKeypad(mode, angleUnit, memoryKeysVisible, …)   // bespoke Box
         else /* Classic, Remix, Tape */
                        -> GridKeypad(layout, mode, angleUnit, memoryKeysVisible, …)
       }
```

**`GridKeypad`** is today's flat weighted-`Column` renderer, generalized two ways:
- Cells become `KeypadCell(action, span = 1)`; a cell renders with `Modifier.weight(span)` (Remix's `0` = span 2). Short rows still pad with `Spacer` weights so column widths stay consistent.
- Its flat row list is `buildKeypadRows(mode, angleUnit, layout, memoryKeysVisible)`: scientific rows (when scientific) → memory row (**only when `memoryKeysVisible`**) → basic rows, where basic rows = `remixBasicRows` for Remix else `classicBasicRows`. Keeping sci + memory + basic as flat siblings in one weighted Column preserves today's exact equal-key-height behavior for grid layouts — the change is genuinely small.

**`ArcKeypad`** is a separate composable (§5). It still renders the scientific grid (when scientific) and the memory row (when visible) as grids above its Arc number-pad-plus-operators Box.

This isolates Arc's geometry in one file, lets Classic/Remix stay data-only variants of one renderer (matching the existing `basicRows` model and the reference prototype), and keeps every block independently previewable.

**Out of scope for the dispatcher:** the landscape keypad (`CalculatorScreenLandscape`'s private `WeightedButtonGrid`) is **not** unified with `GridKeypad`. Landscape ignores `layout` entirely (§6); it gains only the memory-toggle gate. Unifying the two grid renderers is a tempting refactor but unrelated to this milestone.

## 4. Settings & state plumbing (mirror existing patterns)

/** Selectable keypad arrangement. Tape is reserved for v1.7 (not yet in the picker). */

## 5. Remix and Arc

### Remix (small)
Defined in `CalculatorActions.kt` as `remixBasicRows: List<List<KeypadCell>>` beside the existing `basicRows`, reusing the same `CalculatorUiAction`s:
```
AC  %   ⌫   ÷          ← top row swaps Classic's () for ⌫
7   8   9   ×
4   5   6   −
1   2   3   +
[ 0  ·span2 ]  .   =   ← 0 spans 2 cols; = takes the old backspace slot
```
No `()` cell (decision #4). 19 keys vs Classic's 20.

### Arc (the implementation risk — most detail)
New `feature/calculator/ui/components/ArcKeypad.kt`. The Arc *basic block* is a `Box` sized by `BoxWithConstraints`:
- **Number pad:** a 3-col grid on the leading 63% — `7 8 9 / 4 5 6 / 1 2 3 / 0 . ⌫ / [AC·span2] %` (5 rows). `keyH = (boxHeight − 4·gap) / 5`.
- **Operators:** four circles (`÷ × − +`) and an oversized `=` (≈1.38× keyH), absolutely anchored bottom-end. Operators are **stacked programmatically above** the `=` circle so they never overlap at any key height — port the prototype's `arcStart`/`arcStep` math (`arcStart = eqSize + 18; arcStep = (H − arcStart − opSize − 6) / 3`), with `x`-insets `{÷:34, ×:12, −:2, +:0}` curving the arc inward.
- **Arc guide:** a faint 1px circle (`sifr.hairline`) curving behind the operators, `pointerEvents = none`.
- Arc always uses plain gap spacing (opts out of mosaic/hairline framing — matches the prototype).
- **Scientific + Arc:** the sci grid renders above the Arc Box (stacked), same as grid layouts. No special-casing.

**`CalculatorButton` extension (shared dependency):** add an optional `shape: Shape? = null` param (defaults to `RoundedCornerShape(sifr.keyRadius)`). Arc passes `CircleShape` for its operator + `=` circles. The override must also drive the **eq-glow corner radius** (currently hardcoded to `sifr.keyRadius.toPx()` in the `buildGlowBitmap` call) so the Layl `=` glow renders correctly on the circular Arc `=`. Press-scale, drop-shadow, inner-top-highlight, and border modifiers all already key off the shape/`keyRadius` — route them through the effective shape. This is a small, justified change to code we're already in.

## 6. Settings KEYPAD section & landscape

### Settings UI
New section inserted between APPEARANCE (palette) and DISPLAY in `SettingsScreen`:
```
SectionLabel("KEYPAD")
KeypadLayoutPicker(selected = state.settings.keypadLayout, onSelect = { SetKeypadLayout(it) })
SwitchRow("Memory keys", checked = state.settings.memoryKeysVisible, onChange = { ToggleMemoryKeys })
```
**New** `feature/settings/ui/components/KeypadLayoutPicker.kt`, mirroring `ThemePicker`'s `FlowRow` of bordered tiles (selected = 2px `accent` border). Tiles for **Classic / Remix / Arc only** (Tape excluded until v1.7). Each tile is a small **schematic mini-diagram** of the layout (a few cells/dots suggesting the shape — Classic 4×5 grid, Remix grid with a wide bottom-left cell, Arc 3-col pad + a corner arc of dots) plus the localized name.

`SettingsAction` gains `data class SetKeypadLayout(val layout: KeypadLayout)` and `data object ToggleMemoryKeys`; `SettingsViewModel.onAction` handles them via `updateSettings { copy(...) }` (mirrors `SetPalette` / `ToggleFractionResults`).

### Landscape
`CalculatorScreenLandscape` **ignores `keypadLayout`** — Remix/Arc are portrait one-hand concepts; landscape keeps its fixed two-pane scientific|basic split. It **does honor `memoryKeysVisible`**: thread the flag into `BasicBlockLandscape` and gate its `add(memoryRow)`. `CalculatorScreen`'s `CalculatorScreenLandscape(...)` call passes `state` (already carries the flag).

## 11. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Arc operator/`=` overlap at extreme key sizes | Programmatic stacking (`arcStart`/`arcStep`); previews at 46dp + 74dp are the gate |
| eq-glow breaks on circular `=` | `shape` override drives the glow corner radius; Layl-dark Arc preview verifies |
| Equal-key-height regression when refactoring `CalculatorButtonGrid` | Grid layouts keep sci+memory+basic as flat siblings in one weighted Column (today's behavior); only Arc opts out |
| Memory toggle missed in landscape | Explicit thread into `BasicBlockLandscape`; landscape memory-off preview |
| Remix "no parens" surprises users | Intended (decision #4); Classic + Scientific retain parens; picker mini-diagram + naming set expectations |

## 12. Out of scope (YAGNI / deferred)

- **Tape** layout + its in-display history receipt → v1.7.
- **Unifying** portrait `GridKeypad` with landscape `WeightedButtonGrid`.
- **Per-layout landscape** variants (landscape stays one fixed arrangement).
- Any **engine** change; any **`applicationId`/namespace** change; **Arabic-Indic numerals**; **live FX**; **CI/CD** (all tracked elsewhere).
