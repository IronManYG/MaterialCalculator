# Sifr v1.8 — "Language" Design Spec

> **Status:** Draft for review, 2026-06-14.
> **Milestone:** v1.8 in the redesign arc (final milestone before the batched v2.0 Play cut).
> **Branch:** `feature/v1.8-language` off `development` (`d0e9cb1`, which now carries the merged v1.7.x `÷`-glyph + restore-target + "Restore as" label work).
> **Ship:** accumulates toward the single v2.0 Play cut — nothing ships per-milestone.
> **Skills consulted:** `kmp-localization-rtl` (patterns, collapsed to native-Android per its own "Native Android" note), `arabic-localization` (AR copy), plus device-tested skill feedback at `~/AndroidStudioProjects/Rakiza/skill-feedback/kmp-localization-rtl.md`.

## 1. What this milestone delivers

An **in-app language switch** with **live RTL** and a **LANGUAGE section in Settings** — no leaving the app, no trip to system settings. Tapping a language re-renders the whole UI in that language, mirrored if RTL, **in place** (no Activity recreate, no flash; ViewModel / scroll / `SavedStateHandle` state survives).

Concretely:
- `AppLanguage` enum (`System` / `English` / `Arabic`) + DataStore persistence, mirroring every other setting.
- A `SifrLocale` composable in `MainActivity` that applies the chosen locale via `LocalContext` / `LocalConfiguration` / `LocalLayoutDirection` overrides — **synchronously, in composition, re-imposed on every config change** (see §5).
- A Settings **LANGUAGE** section (new top section), built as a **scalable selectable list** (one row per language, check on the selected one) — not a fixed segmented pill — so future languages are new rows + strings with zero UI rework.
- **Role-based per-palette Arabic typography:** numbers, operators, the display, and keypad keys keep the palette's signature font in every language; only translated *chrome text* (`uiFamily`) switches to a **hand-matched Arabic font per palette** when Arabic is active.

### Locked decisions (this session)

1. **Mechanism = in-place live recompose, NO AppCompat.** Apply the locale via Compose `LocalContext`/`LocalConfiguration`/`LocalLayoutDirection` overrides in the same reactive flow that already recomposes `SifrTheme(palette=…)`. Rejected: `AppCompatDelegate.setApplicationLocales` (would force `androidx.appcompat` + `AppCompatActivity` + reparenting `Theme.Sifr` off `Theme.Material3.*` + a `locales_config.xml`/manifest service + an Activity-recreate flash — heavy and against the app's deliberate pure-`ComponentActivity` / Material3 stance). **Trade accepted:** the app will not register in the API 33+ *Settings → System → App languages* picker, and won't sync with an OS-set per-app locale.
2. **Options = System / English / العربية (3-way).** `System` follows the device locale.
3. **Typography = role-based, per-palette Arabic pairing.** Only `uiFamily` swaps for Arabic; `displayFamily`/`keyFamily` never change. Digits always render on the palette number font. Approved pairings in §8.
4. **Picker = scalable list, placed as a new top section** above "Appearance".
5. **Shipped languages in v1.8 = System/EN/AR only; the infrastructure is built to scale.** Tier-1 Latin languages (Spanish, Portuguese-BR, French, German, Indonesian, Turkish, Italian, Vietnamese; then Russian) are a **fast follow-up (v1.8.x)** — just `values-XX/strings.xml` + enum/list rows, no font work. Non-Latin (Hindi/Devanagari, CJK) is a later **font-aware** effort (it reopens the per-palette-font problem this milestone solves for Arabic). See §11.

## 2. Constraints inherited

- **Engine untouched** — zero changes to `ExpressionWriter → ExpressionParser → ExpressionEvaluator`. Number formatting already uses `Locale.ROOT` (`ExpressionWriter:379,386`), so the locale switch needs **no `Locale.setDefault` mutation** and cannot perturb calculation. **Unit-test baseline stays 148.**
- **Keypad stays `LayoutDirection.Ltr`** in every layout/orientation (math reads L→R) — already enforced; the locale override must not leak RTL into the keypad/display. RTL math mirrors with the locale but reads L→R (`textDirection = Ltr` + `textAlign` per locale) — already implemented app-wide; see [[fidelity-match-prototype]].
- **New strings need en + ar** — `lintDebug` enforces `MissingTranslation`. No positive `letterSpacing`/uppercase on Arabic letters (guard LTR-only — the existing `SectionLabel` already does).
- **`applicationId` untouched** (`com.gaddal.materialcalculator`); namespace stays `dev.gaddal.sifr`.
- **Previews are the visual contract** — every new/changed surface ships `@Preview` coverage; add an Arabic-locale + RTL Settings preview (§10).
- **Build with `sh gradlew`**, never `./gradlew`; never `git add gradlew`. `docs/` is gitignored — commit this spec with `git add -f`.
- **Confined ripple** — controls own their tap; the language rows are a genuine list whose tap *is* the action, so a whole-row `onClick` is correct here (the documented exception). See [[confined-ripple-controls]].

## 3. Why most of the `kmp-localization-rtl` pitfalls don't apply

The skill is Compose-Multiplatform-framed; Sifr is **standard Android Compose** (`androidx.compose.ui.res.stringResource(R.string.x)`, which reads `LocalConfiguration.current` and returns `LocalContext.current.resources.getString(id)`). That `LocalContext`/`LocalConfiguration` pair is a real override seam — which CMP lacks (CMP `Res.string` reads `LocaleList.getDefault()`, and `LocalComposeEnvironment` is `internal` in CMP ≤1.11.0). Consequences, cross-referenced to the Rakiza device-found feedback:

| Rakiza feedback entry (device-found) | Root cause | Sifr (Android)? |
|---|---|---|
| #2/#3 — `key(locale){}` cancels `viewModelScope`, wipes `rememberSaveable`/nav back stack ("two-tap" bug) | CMP must destroy+recreate the subtree to force `Res.string` re-resolution | **N/A.** Providing new `LocalContext`/`LocalConfiguration` re-resolves `stringResource` **in place** — **no `key(locale)`**, so no disposal, no scope cancellation, no saveable reset. |
| #4 — background `AppLocalizer` *races* the recomposition (layout flips, strings stay old-language) | two independent flow collectors, no happens-before | **Designed out.** No background `AppLocalizer`; the override is computed **synchronously in composition** from the collected `settings.language`. |
| #5 — one-time apply reverts on a non-recreating config change (180°/reverse-portrait) | framework republishes `Configuration` with device locale; apply keyed only on the locale tag | **Guarded.** The localized context is `remember(LocalConfiguration.current, language){…}` — re-derived on every config change (§5). |
| #1 (Wasm seam), #6 (`js()` arrow-body) | Wasm/webpack codegen | **N/A** — Android-only, no Wasm target. |

## 4. State & persistence (mirror existing patterns)

Byte-for-byte the `palette` (enum) pattern already in the repo.

```kotlin
// core/domain/settings/AppLanguage.kt
/** Null tag = follow the device locale. */
enum class AppLanguage(val tag: String?) { System(null), English("en"), Arabic("ar") }
```
- `AppSettings` gains `val language: AppLanguage = AppLanguage.System`.
- `SettingsRepositoryImpl`: `KEY_LANGUAGE = stringPreferencesKey("app_language")`; write `updated.language.name`; read with the `runCatching { AppLanguage.valueOf(it) }.getOrNull() ?: AppLanguage.System` fallback. Survives process death via DataStore.
- `SettingsAction.SetLanguage(language: AppLanguage)`; `SettingsViewModel.onAction` → `repo.update { copy(language = it) }`. (No `SavedStateHandle` change needed.)

## 5. Mechanism — `SifrLocale`

A new composable wrapping the existing tree in `MainActivity.setContent`:

```kotlin
val settings by settingsRepo.observe().collectAsStateWithLifecycle(initialValue = AppSettings())
SifrLocale(language = settings.language) {                       // Context/Config/LayoutDirection
    SifrTheme(palette = settings.palette, themeMode = settings.themeMode,
              language = settings.language) {                    // language drives the Arabic font swap (§8)
        NavRoot(windowSizeClass = calculateWindowSizeClass(this))
    }
}
```

```kotlin
// core/ui/locale/SifrLocale.kt
@Composable
fun SifrLocale(language: AppLanguage, content: @Composable () -> Unit) {
    val tag = language.tag ?: run { content(); return }          // System → follow device, no override
    val configuration = LocalConfiguration.current               // ← KEY on this: re-fires on config change (entry #5)
    val baseContext = LocalContext.current
    val locale = remember(tag) { Locale.forLanguageTag(tag) }
    val localized = remember(configuration, tag) {               // ← synchronous, in composition (entry #4)
        val cfg = Configuration(configuration).apply { setLocale(locale); setLayoutDirection(locale) }
        baseContext.createConfigurationContext(cfg)
    }
    val rtl = TextUtils.getLayoutDirectionFromLocale(locale) == View.LAYOUT_DIRECTION_RTL
    CompositionLocalProvider(
        LocalContext provides localized,
        LocalConfiguration provides localized.resources.configuration,
        LocalLayoutDirection provides if (rtl) LayoutDirection.Rtl else LayoutDirection.Ltr,
        content = content,
    )
}
```

Switch flow: tap language row → `repo.update` → DataStore emits → `collectAsStateWithLifecycle` re-emits → `SifrLocale` recomposes with the new `language` → the provided locals change → the subtree **recomposes in place** (not disposed; `remember`/`rememberSaveable` survive) → every `stringResource` re-resolves and `LocalLayoutDirection` flips. No `recreate()`, no flash.

**Notes:**
- `LocalContext` is a `staticCompositionLocalOf`; providing a new value recomposes the whole content lambda (intended — full re-resolution) but does **not** dispose remembered state.
- `windowSizeClass` is computed from the Activity (locale-independent), so it's unaffected.
- `System` returns early (no override) so switching *to* System on, e.g., an English device cleanly reverts to device locale + LTR.

## 6. Settings — LANGUAGE section (scalable list)

A new section placed **first**, above "Appearance", following the `SectionLabel` + `SifrCard` + `SifrRow` grammar:

```
SectionLabel("LANGUAGE")            // "اللغة" in ar
SifrCard {
    AppLanguage.entries.forEachIndexed { i, lang ->
        if (i > 0) SifrRowDivider()
        SifrRow(
            label = lang.displayLabel(),               // "System default" / "English" / "العربية"
            onClick = { onAction(SettingsAction.SetLanguage(lang)) },   // genuine whole-row action
            trailing = { if (lang == state.settings.language) Icon(Check, …, tint = accent) },
        )
    }
}
```
- Each language's own name is shown in its own language (`English`, `العربية`); `System` is localized ("System default" / "حسب النظام").
- Selected row shows a check (accent). Adding a Tier-1 language later = one enum entry + its `values-XX` file + (its label is its own endonym) — the list grows automatically.
- The row tap is the documented confined-ripple exception (a real list row whose tap is the action), so `SifrRow(onClick=…)` is used here.

## 7. Live RTL & icon mirroring

RTL is already handled app-wide (mirrored alignment, forced-LTR math). `SifrLocale` just drives `LocalLayoutDirection`, so the existing RTL-aware code flips live. Audit pass: confirm directional icons use `Icons.AutoMirrored.*` (the Settings back arrow already does) and that no decorative vector needs `autoMirrored`. The keypad/display stay LTR (already enforced) regardless of locale.

## 8. Typography — role-based per-palette Arabic pairing

`uiFamily` is the only family that varies by language. Add **one** field to `SifrColors`:

```kotlin
val arabicUiFamily: FontFamily? = null   // per-palette Arabic chrome font; null → fall back to uiFamily
```
In `SifrTheme`, when the resolved locale is Arabic:
```kotlin
val resolved = if (isArabic && base.arabicUiFamily != null) base.copy(uiFamily = base.arabicUiFamily) else base
CompositionLocalProvider(LocalSifrColors provides resolved) { MaterialTheme(typography = sifrTypography(resolved), …) }
```
Every `sifr.uiFamily` reader (Settings, History chrome, chips, rows, segmented, top bar) and `sifrTypography` get the Arabic font for free; `displayFamily`/`keyFamily` (display, keys, History results, Tape) are untouched — numbers/keys keep the palette font in every language.

New families in `SifrFonts.kt` via the existing `family("…")` Google-Fonts one-liner (exact Google Fonts names below; verify weight availability at build via `dependency-version-lookup`). **Amiri is already wired.**

| Palette | Latin chrome font | **Arabic font** (Google Fonts family name) |
|---|---|---|
| **Layl** | Space Grotesk | **Cairo** |
| **Bayan** | Archivo | **Tajawal** |
| **Raqim** | Space Grotesk (serif identity) | **Amiri** *(already wired)* |
| **Farah** | Baloo 2 | **Baloo Bhaijaan 2** |
| **Mizan** | IBM Plex Mono | **IBM Plex Sans Arabic** |
| **Dynamic** | Space Grotesk | **Cairo** (= Layl) |

**Two edge cases to handle explicitly (not let the swap break):**
1. **`SifrBrand` Latin wordmark** ("SIFR"/"Sifr") currently reads `uiFamily` → would ride the Arabic swap. Route it to `displayFamily` (the palette's hero font, Latin, never swapped) so the Latin wordmark keeps its palette look in Arabic mode. The صفر Arabic wordmark already uses Amiri explicitly.
2. **Display error text** — if `CalculatorDisplay` renders a translated error *word* (e.g. "Error"/"خطأ") on `displayFamily`, it would fall to the system Naskh in Arabic. Verify during implementation; if it's a word (not a glyph), route that one string to the Arabic family. (Numeric error states are unaffected.)

## 10. Previews & device QA

**Previews:** add to `SettingsScreen.kt` — a Settings preview with `language = Arabic` (forces the Arabic font + RTL via a `CompositionLocalProvider(LocalLayoutDirection provides Rtl)` in the preview), and a `@PreviewLightDark` on the new LANGUAGE section. **Device QA (both connected devices — NTH-NX9 `…AXPMVB1C06003152…` and Honor DNP-NX9 `…A3SQUT5919003002…`):** see [[device-adb-screenshot-technique]].
1. Live **en↔ar** switch from the LANGUAGE list — whole UI flips language + RTL, **no flash**, and you stay on the Settings screen (state survives).
2. Each palette's **Arabic font** renders on chrome text; numbers/keys stay on the palette font.
3. **Rakiza #5 repro** — set app-locale ≠ device locale, then 180°/reverse-portrait rotation; confirm strings do **not** revert to the device language (the `LocalConfiguration`-keyed `remember` re-imposes). (DNP-NX9 is where Rakiza reproduced this.)
4. `System` follows the device; switching back to System reverts cleanly.

## 11. Out of scope (flag, don't sneak in)

- **Tier-1 Latin languages** (es, pt-BR, fr, de, id, tr, it, vi; then ru) — fast follow-up **v1.8.x**, strings + enum/list rows only (no fonts, no UI rework).
- **Non-Latin languages** (Hindi/Devanagari, Chinese/Japanese/Korean) — later **font-aware** milestone; reopens per-palette font pairing + large CJK assets.
- **Eastern-Arabic numerals (٠–٩)** in the display — stays Western per current design; the `٠` empty-state glyph is decorative.
- **Per-glyph mixed-string fallback** (Latin font inside a single Arabic string) — role-based assignment covers ~95%; true per-glyph needs `Typeface.CustomFallbackBuilder` (API 29+) vs minSdk 24. Rejected this session.
- **OS "App languages" picker integration** (API 33+) — would require the AppCompat path rejected in §1.
- **`RestoreTarget.FrozenState`** and other pre-existing backlog items — unrelated. See [[sifr-redesign-roadmap]].
